# 07. 実装計画

1 PR = 1 つの機能 を目安に、上から順に積みます。各 PR は main から切り、CI（lint / typecheck / test）が通った状態で出します。

| # | PR | 内容 | 動かして確認できること |
|---|---|---|---|
| 1 | 土台 | Vite + React + Hono + Workers、Tailwind、Drizzle + D1、Vitest、GitHub Actions（CI）、タブバーの空画面 | `wrangler dev` で空の画面が出る |
| 2 | DBスキーマ | 02 のテーブルとマイグレーション、ULID、共通エラー処理 | マイグレーションがローカル D1 に当たる |
| 3 | 食材マスタ | API + 画面（S12）、初期データ 50 件（目安値） | 食材と販売単位を登録・修正できる |
| 4 | レシピ | API + 画面（S09, S10） | レシピを手で登録・編集できる |
| 5 | 在庫・冷蔵庫ビュー | 期限計算（純粋関数）、API、画面（S02）、ホーム（S01）の期限間近 | 在庫を手で入れて期限順に見られる |
| 6 | レコメンド | `recommend.ts` と単体テスト、献立 API、画面（S03） | 料理を選ぶと提案が出て確定できる |
| 7 | 買い物リスト | 生成、チェック→在庫登録、画面（S04） | 買ったものをチェックすると在庫に入る |
| 8 | 下ごしらえ・袋詰め | `prep.ts`、袋の判定、画面（S05, S06, S07） | 食材ごとの下ごしらえと袋の保存ができる |
| 9 | 調理 | 画面（S08）、作った・余りの更新、plan の完了 | 1 サイクルが最後まで回る |
| 10 | AI | プロバイダ層、URL 取り込み（S11）、補完提案 | URL からレシピの下書きができる |
| 11 | デプロイ | 本番 D1、Cloudflare Access、main マージで自動デプロイ | スマホから使える |

PR 11 は手順書（Access の設定など本人が Cloudflare 画面で行う作業）を含みます。早くスマホで触りたい場合は、5 の後に前倒しできます。

## MVP 後（あるとよい）

- 買い物リストのオフライン（PWA、Service Worker、チェック操作のキュー）
- 調味料など常備品の管理（切れそうなときだけ買い物リストに載せる）
- 週 1 回の R2 へのバックアップ
- 設定画面

## テスト方針

| 対象 | 方法 |
|---|---|
| レコメンド、販売単位、期限、下ごしらえ集約 | Vitest の単体テスト（厚めに） |
| API | `@cloudflare/vitest-pool-workers` でローカル D1 を使った結合テスト（主要な流れ） |
| AI | FakeProvider で流れだけテスト。実プロバイダは手動確認 |
| 画面 | MVP では手動確認。1 サイクル通しの E2E（Playwright）は余裕があれば追加 |
