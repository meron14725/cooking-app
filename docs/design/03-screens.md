# 03. 画面と遷移

スマホ縦画面で、上から下へ読めば使えることを優先します。下部にタブバーを置きます。

| タブ | 画面 |

## 1サイクルの流れ

```
S01 ホーム
 │「食べたい料理を選ぶ」
 ▼
S03 献立を組む ─────────────── (plan: draft)
 │ 1. 食べたい料理を1つ以上選ぶ
 │ 2. 提案（追加料理と買う量）を最大3案表示
 │ 3. 1案を選ぶ / 料理を入れ替える / 足りなければ「AIに1品提案してもらう」→ S11相当の確認
 │ 4. 確定
 ▼
S04 買い物リスト ───────────── (plan: shopping)
 │ チェック → 在庫に登録
 │「買い物完了」
 ▼
S05 下ごしらえ ─────────────── (plan: prepping)
 │ 食材ごとに切る。直前に切るものは「切らずに残す」枠
 │「下ごしらえ完了」
 ▼
S06 袋詰め
 │ 料理ごとに袋を確認し、冷蔵/冷凍を決めて保存
 │「保存完了」
 ▼
S01 ホーム / S02 冷蔵庫ビュー ─ (plan: stored)
 │ 食べたいときに袋を選ぶ
 ▼
S08 調理
 │ 直前作業 → 入れる → ボタン → 「作った」
 │ 余った食材の量を確認（在庫に残す）
 ▼
（全部の袋を作り終えたら plan: done）
```

途中で画面を閉じても、献立タブを開けば今の状態の画面に戻ります。

## 各画面の要点

### S03 献立を組む

- 上部: 選んだ料理（anchor）
- 提案カード（最大3案）: 追加する料理名、買い物の点数、余る食材とその量、使える在庫（期限間近は強調）、合計カロリー
- 提案カードの中で料理を外す・入れ替えると再計算
- 余りが大きいときは「余る食材で AI に 1 品提案してもらう」ボタン

### S04 買い物リスト

- 売り場順（野菜 → 肉 → 魚 → 豆腐・卵・乳製品 → 乾物 → 調味料 → その他）
- 1行: 「玉ねぎ 3個入り × 1（使うのは 2 個）」
- チェックは即時反映（楽観的更新）。通信が切れていても画面上はチェックでき、復帰時に送る（PWA 対応は あるとよい。MVP では TanStack Query のリトライで最低限対応）

### S05 下ごしらえ

```
■ 今切るもの
  玉ねぎ 2個
    ・カレー用 くし切り 1個
    ・スープ用 薄切り 1個
  にんじん 1本 ...

■ 切らずに残すもの（直前に切る）
  じゃがいも 2個 … 冷凍できないので直前に切る（カレー）
  豆腐 1丁 …（麻婆豆腐）
```

### S06 袋詰め

- 袋ごと: 料理名、中身、冷蔵/冷凍（初期値は自動判定）、使用期限、直前作業が残っている食材
- 冷凍できないものが入っているのに冷凍を選ぶと警告

### S08 調理

1. 直前作業（例: 豆腐を切る、じゃがいもを切る）
2. 入れる順（袋 → 直前に切ったもの → 水・調味料）
3. ホットクックの設定（`hotcook_mode`）
4. 冷凍のまま入れる場合の注意（袋が冷凍なら表示）
5. 「作った」→ 余った食材の量を確認

## UI の方針

- 文字は大きめ、タップ領域は 44px 以上
- 期限間近は色だけでなくラベル（「あと1日」）でも示す
- 画面とメッセージは日本語
